> 经验声明：本文是 AI 编程基础概念系列的第一篇。这个系列会把 LLM、Token、Context、Tool、MCP 和 Skill 拆开讲。先从最容易被神化的 LLM 开始。

很多人第一次用 ChatGPT、Claude、Cursor 或 Codex，会下意识觉得它们像一个“懂编程的人”。

这个感觉不奇怪。

因为它们会解释代码，会写函数，会看报错，会总结需求，有时候甚至能给出很像资深工程师的建议。

但如果你想真的用好 AI 编程工具，第一件事不是把它想成一个无所不知的程序员，而是先理解它的底层身份：

**LLM 是 Large Language Model，大语言模型。**

它最核心的能力，不是像人一样生活、记忆和理解世界，而是根据前面的内容，预测后面最可能出现什么。

## LLM 到底在做什么

你可以先把 LLM 理解成一个很会读文字、接文字、写文字的系统。

当你输入：

```text
帮我写一个登录接口。
```

模型并不是像人一样打开 IDE、查需求、回忆项目历史，然后慢慢想业务边界。

它会根据训练中见过的大量代码、文档、问答、教程和错误日志，推断这个请求后面大概率应该出现什么内容。

所以它可能会生成：

- 一个接口路由。
- 一个参数校验逻辑。
- 一个数据库查询。
- 一个密码校验过程。
- 一个 token 生成过程。
- 一段解释说明。

这就是 LLM 的强项：它特别擅长从语言和代码模式里推断下一步。

## 为什么 LLM 能写代码

代码本身也是语言。

函数名、变量名、类型定义、注释、错误信息、接口文档、README、测试用例，全都是文本。

LLM 在训练时见过大量这样的文本，所以它不只是会写自然语言，也能生成结构化的代码。

这也是为什么它适合做这些事：

- 解释一段陌生代码。
- 根据需求生成代码草案。
- 根据报错推测可能原因。
- 把复杂逻辑改写得更清楚。
- 帮你整理接口文档。
- 根据测试失败信息定位问题。

但这里有一个关键点：

**LLM 会写代码，不代表它天然懂你的项目。**

它不知道你们公司的历史债务，不知道某个字段为什么不能删，不知道某个接口为什么要兼容旧版本，也不知道产品经理上个月临时改过什么规则。

这些信息如果没有进入它当前能看到的材料里，它就只能凭通用经验推理。

## 不要把 LLM 当成全知程序员

新人最容易踩的坑，是把 LLM 当成一个已经熟悉项目的同事。

比如直接问：

```text
这个功能怎么改？
```

但你没有告诉它：

- 你说的是哪个功能。
- 当前代码在哪。
- 线上问题是什么。
- 不能改哪些边界。
- 改完需要跑什么测试。

这时候模型可能仍然会给你一个回答，而且看起来很完整。

问题是，这个回答可能只是“合理”，不一定“正确”。

AI 编程里很多翻车，不是模型完全没能力，而是它拿到的信息不够具体。

更准确的用法应该是：

```text
我在改用户资料页的保存逻辑。
当前问题是提交后接口返回 400。
相关文件是 profile/service.ts 和 profile/form.tsx。
报错信息如下。
请先判断可能原因，不要直接大改结构。
```

这时 LLM 才开始像一个进入现场的协作者。

## LLM 是大脑，但不是整个系统

AI 编程工具不只是 LLM。

如果只有 LLM，它只能根据你贴给它的内容回答。

真正让 AI 编程工具变强的，是 LLM 周围的能力：

- Token 决定文字怎么被模型处理。
- Context 决定模型这次看到了什么。
- Tool 让模型可以读取文件、运行命令、搜索代码。
- MCP 让外部工具用标准方式接进来。
- Skill 告诉模型某类任务应该按什么流程做。

所以可以先记住一句话：

```text
LLM 是大脑，但 AI 编程不是只有大脑。
```

模型本身负责理解、推理和生成。

但它要想在真实项目里稳定工作，还需要上下文、工具、流程和约束。

## 总结

如果你刚接触 AI 编程，理解 LLM 时先别急着追模型参数、排行榜和各种神奇演示。

先记住这几点：

- LLM 是大语言模型。
- 它的核心能力是基于上下文生成后续内容。
- 它很擅长处理文字、代码、日志和文档。
- 它不天然知道你的项目和业务背景。
- 它需要 Context、Tool 和 Skill 才能真正进入工作流程。

把 LLM 理解清楚之后，再看 Token 就会容易很多。

因为模型不是直接“读懂文字”，它会先把文字切成一小块一小块的 token。
