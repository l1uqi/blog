Token：模型眼里的文字颗粒

2026-05-06 · 4 min · 1.3k words · AI

经验声明：本文是 AI 编程基础概念系列的第二篇。上一篇讲 LLM，这一篇讲 Token。Token 看起来很底层，但它直接影响上下文长度、成本、速度和 AI 是否容易抓住重点。

人看文字，通常是按字、词、句子来理解。

模型看文字，不是这样。

LLM 在处理文字之前，会先把文字切成一小块一小块的 token。

你可以把 token 理解成：

这些颗粒可能是一个英文单词，也可能是半个单词、一个汉字、几个汉字、一个标点，甚至是一段代码符号。

Token 不是字数

这是新人最容易误解的地方。

Token 不等于汉字数，也不等于英文单词数。

比如：

在人眼里，这就是一句很短的话。

但在模型眼里，它会先被 tokenizer 切成若干 token，然后再转成模型可以处理的数字。

英文、中文、空格、标点、代码里的括号、引号、缩进，都可能占 token。

所以你不能简单用“我贴了多少行”来判断上下文大小。

一大段报错日志、一整个组件文件、一份接口文档、几条项目规则，只要放进对话里，都会消耗 token。

为什么 Token 对 AI 编程重要

Token 重要，是因为模型的一切输入和输出都要经过它。

你发给 AI 的内容会消耗 token：

  • 你的问题。
  • 代码文件。
  • 报错日志。
  • 历史对话。
  • 项目规则。
  • 工具说明。
  • 外部工具返回的数据。

AI 输出的内容也会消耗 token：

  • 解释说明。
  • 修改方案。
  • 代码片段。
  • 测试结论。
  • 总结报告。

这会带来几个直接影响。

第一，token 会影响上下文空间。

每个模型都有一次最多能处理多少 token 的限制。这个限制通常叫 Context Window，也就是上下文窗口。

如果你塞进去的内容太多，旧内容可能会被压缩、裁剪，或者重点信息被大量无关内容冲淡。

第二，token 会影响成本和速度。

输入越多，模型要处理的内容越多，成本和响应时间通常也会上升。

第三，token 会影响模型注意力。

不要误以为上下文窗口大，就可以随便塞材料。

模型能看到很多内容，不代表它一定能把重点抓得很好。

不要把整个项目都丢给 AI

很多新人会这样问：

这个提问方式看起来很勤快，实际效果经常不好。

因为这会让 AI 面对一大堆没有筛选过的 token。

它可能看到了很多文件，但不知道哪个最关键。

它可能读到了很多规则，但不知道这次任务真正相关的是哪几条。

它可能被大量无关代码干扰，反而漏掉真正重要的报错信息。

更好的方式是先收窄问题：

等 AI 判断出可能相关的文件，再把这些文件逐步放进上下文。

这就是 AI 编程里很重要的原则：

不是给得越多越好，而是给得越准越好。

Token 和代码有什么关系

代码通常比普通文章更容易消耗 token。

原因很简单：

  • 代码里有大量符号。
  • 代码里有缩进和换行。
  • 类型定义可能很长。
  • 错误日志里有调用栈。
  • JSON、SQL、正则表达式会被切得很碎。

所以在让 AI 看代码时，要特别注意材料筛选。

比如你可以优先提供：

  • 出错函数。
  • 相关类型定义。
  • 调用链入口。
  • 测试失败输出。
  • 最近改动范围。

先不要一次性贴整个仓库。

如果 AI 有工具能力，让它自己搜索代码、读取文件、运行测试，通常比你手动贴一大堆内容更稳。

总结

Token 是模型处理文字和代码的基本单位。

理解 token 之后，你会更容易明白为什么 AI 有时会“忘记”、为什么上下文不能无限塞、为什么清晰的问题比大量材料更重要。

可以先记住这几句话：

  • Token 不是字数。
  • 所有输入和输出都会消耗 token。
  • 上下文窗口本质上按 token 计算。
  • AI 编程不是材料越多越好，而是相关信息越准越好。
  • 代码、日志、JSON、类型定义都可能很吃 token。

如果说 Token 是模型读文字的颗粒，那么 Context 就是这一次真正摆到模型面前的材料。
