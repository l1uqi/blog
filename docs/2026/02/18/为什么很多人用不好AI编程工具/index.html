最近我发现一个很有意思的现象：公司里越来越多人开始使用 AI 编程工具，比如 Cursor、Claude Code、Codex、Copilot 等等，但实际效果往往没有想象中那么好。

有些人用了几天之后，会觉得 AI 不稳定、答非所问、改代码容易乱来；也有人觉得 AI 很适合写 demo，但一进入真实业务项目就开始失控。

我的判断是：这并不完全是模型的问题。很多时候，问题出在我们没有给 AI 一个可靠的工作环境。

更具体地说，最常见的两个问题是：

  1. Rules 几乎没有。
  2. Context 严重受限。

这两个问题叠加在一起，就会导致 AI 看起来像一个“聪明但不熟悉项目的新同事”：它能写代码，但不知道团队规矩；它能理解当前文件，但记不住长期背景；它能回答眼前问题，但很难持续参与一个真实项目。

这种用法在小场景里当然有效。但真实项目并不是一道孤立的题目，它背后通常有很多隐含规则：

  • 这个项目使用什么状态管理方式？
  • 接口错误应该如何统一处理？
  • 组件命名有没有约定？
  • 是否允许直接修改公共组件？
  • 提交前是否必须补测试？
  • 哪些逻辑来自历史兼容，不能随便重构？
  • 业务字段背后有没有特殊含义？

人类工程师加入项目时，会通过文档、代码 review、同事口头提醒慢慢吸收这些规则。但 AI 不会自动知道这些东西。

如果我们不给它 Rules，它只能根据当前上下文和通用经验做判断。

而通用经验在真实业务代码里，经常是不够的。

两个最常见的问题

我观察下来，很多 AI 编程效果不好，最常见是两个原因。

第一个是 Rules 几乎没有。

没有 Rules，AI 不知道项目边界。它不知道哪些文件不能轻易改，不知道接口错误要怎么统一处理，也不知道团队对测试、提交、重构有什么要求。

第二个是 Context 组织得不好。

Context 不是“你给 AI 的资料越多越好”。它是模型当前这一次推理真正能看到的工作台。工作台上缺关键代码，AI 就会瞎猜；工作台上堆满无关文档，AI 又会抓不住重点。

所以 AI 编程真正难的不是“怎么写一句神奇 prompt”，而是怎么让模型在正确的时机看到正确的信息。

我认为更合理的结构

要让 AI 真正进入工程协作，而不是停留在临时问答，我认为至少需要五层结构：

第一层：Rules

Rules 负责放稳定、通用、必须遵守的规则。

例如：

  • 项目技术栈。
  • 代码风格。
  • 测试要求。
  • Git 工作流。
  • 安全边界。
  • 回答偏好。

这部分应该尽量短，但要足够明确。

第二层：Skills

Skills 负责放可复用的流程。

例如：

  • 如何处理 TAPD 需求。
  • 如何修复缺陷并回写状态。
  • 如何执行 TDD。
  • 如何生成变更摘要。
  • 如何完成发布前检查。

Rule 是红线，Skill 是流程。前者保证 AI 不乱来，后者引导 AI 把复杂任务一步步做完。

第三层：Context

Context 负责承载模型当前这一次任务真正需要看的信息。

例如：

  • 当前需求。
  • 相关代码。
  • 错误日志。
  • 测试结果。
  • 必要的规则和文档片段。

Context 的核心不是多，而是准。

第四层：Project Map

Project Map 负责告诉 AI 应该先去哪里找。

比如新增接口看哪里，修改权限看哪里，公共组件修改前要检查哪些调用方。

第五层：Memory

Memory 负责保存长期上下文，并在需要时检索出来。

例如：

  • 用户偏好。
  • 项目历史决策。
  • 模块说明。
  • 数据库 schema。
  • 常见问题。
  • 需求背景。

这部分不应该全部塞进 prompt，而应该按需搜索。当前任务需要什么，就取回什么。

这不是工具问题，而是工作方式问题

很多人用不好 AI，不是因为不会写 prompt，而是因为没有把 AI 当成一个需要工作环境的协作者。

一个合格的 AI 编程环境，至少要回答三个问题：

  1. 它必须遵守什么规则？
  2. 它当前这次任务应该看到什么上下文？
  3. 它应该按什么流程完成任务？
  4. 它应该先去项目哪里找？
  5. 它如何获取当前窗口之外的长期上下文？

Rules 解决第一个问题。

Context 解决第二个问题。

Skills 解决第三个问题。

Project Map 解决第四个问题。

Memory 解决第五个问题。

缺任何一个，AI 都很容易回到“临时问答工具”的状态。

总结

AI 编程工具真正的价值，不在于它能不能帮我们写几行代码，而在于它能不能逐渐理解项目、遵守规则、记住背景，并参与到真实工程流程中。

如果没有 Rules，AI 不知道边界。

如果没有 Context，AI 无法延续理解。

如果没有 Memory，AI 每次都在重新开始。

所以我越来越相信，未来 AI 编程的关键不是单次 prompt 写得多漂亮，而是能否建立一套稳定的协作基础设施。

Rules 是边界，Context 是工作台，Memory 是让 AI 真正长期参与项目的那一层。
